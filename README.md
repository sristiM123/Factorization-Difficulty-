# Can the Public Modulus Predict Factorization Difficulty?

Code and data for the paper *Can the Public Modulus Predict Factorization
Difficulty? An Empirical Algorithm-Selection Study of Semiprimes at 32–160 Bits*.

The repository contains a benchmark of 10,000 RSA-style semiprimes (32–160 bits,
four controlled factor structures) with measured runtimes for Pollard's rho,
Pollard's p−1, ECM and Fermat's method, the 39 public-modulus features used in
the paper, and a single script that reproduces every number the paper reports,
including the size-only baselines, the Fermat-vulnerable 492-key set, the
parallel top-2 portfolio analysis and the hidden-factor analysis.

## What is in the paper, and where it comes from

| Paper result | Produced by |
|---|---|
| Benchmark dataset, runtimes, hidden factors | `scripts/run_dataset_generation.py` (or `notebooks/dataset_generation.ipynb`) → `data/` |
| All tables and numbers in Sections 4–5 | `scripts/reproduce_paper.py` → `results/paper/` |
| Architecture ablation (stacked ensemble vs. single Random Forest) | `notebooks/02c_simplified_architecture.ipynb`, `notebooks/validation.ipynb` |
| 5-fold CV of candidate regressors, feature-group ablation | `notebooks/additional_experiments.ipynb` → `results/tables_additional/` |
| Figures 2–8 | `results/figures*/` (generated by the notebooks above) |

`results/paper/paper_numbers.json` is the machine-readable record of the
numbers cited in the manuscript, produced by `scripts/reproduce_paper.py`.

## Quick start

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m pytest -q                # 36 unit tests, < 5 s

# Reproduce every reported number from the released data (≈ 15 min on a laptop;
# the Fermat-vulnerable benchmark is the slow part)
python scripts/reproduce_paper.py

# Fast subset, skipping the 492-key benchmark and the bootstrap
python scripts/reproduce_paper.py --skip-fermat --skip-bootstrap

# Regenerate the dataset from scratch (several hours: 10,000 moduli × 4 algorithms)
python scripts/run_dataset_generation.py
```

Experiments in `reproduce_paper.py` can be selected individually, e.g.
`--only E6 E7` for the algorithm-selection and portfolio analysis.

## Layout

```
config/settings.py          seeds, bit-length tiers, structure shares, model hyperparameters
src/generators.py           prime pool and semiprime generation (four factor structures)
src/features.py             39 features computed from N alone
src/benchmarks.py           Pollard's rho, Pollard's p-1, ECM (sympy), Fermat; per-algorithm budgets
src/utils.py                seeding, checksums, logging
scripts/run_dataset_generation.py   builds data/raw and data/processed
scripts/reproduce_paper.py          reproduces the paper's tables and numbers
tests/                      unit tests for generators, features and benchmarks
data/raw/                   semiprimes_raw.csv, hidden_factors.csv, benchmark_results.csv
data/processed/             dataset_with_features_and_runtimes.csv (10,000 rows)
data/meta/                  dataset checksum and environment snapshot
notebooks/                  exploratory notebooks used during development
results/                    figures and tables produced by the notebooks and scripts
archive/pqc_and_stacking/   earlier material on stacked ensembles and PQC scoring, not used in the paper
```

## Benchmark protocol

Each algorithm runs once per modulus under a work bound and a wall-clock cap:
rho ≤ min(5·10⁶, max(5·10⁴, 2^(⌊b/4⌋+2))) iterations and 1 s; p−1 stage 1 to
B₁ = min(5·10⁴, max(10³, 200·b)) and 0.5 s; ECM (sympy defaults, one trial,
fixed seed) 3 s; Fermat ≤ min(5·10⁵, max(10⁴, 1000·b)) iterations and 1 s.
A run that exceeds its cap is recorded as a timeout at the cap. The regression
target is log₂ of the fastest successful runtime; the classification target is
the fastest algorithm. 633 of the 10,000 moduli are factored by no algorithm
within budget and are excluded from regression and selection (they are used by
the factorability classifier).

The environment snapshot of the original run is in `data/meta/dataset_metadata.json`.
Absolute runtimes depend on hardware; algorithm labels and the relative
comparisons in the paper are what the benchmark is designed to support.

## Reproducibility notes

* Global seed 42 everywhere; the dataset checksum (MD5) is stored in
  `data/meta/dataset_metadata.json`.
* Re-running `reproduce_paper.py` on a different scikit-learn / XGBoost
  version moves third-decimal values (e.g. R² 0.558 vs 0.560) but not any
  conclusion; the manuscript reports the values from `results/paper/`.
* The Fermat-vulnerable set is regenerated by the script from seed 42 and is
  also saved to `results/paper/E12_fermat_vulnerable_set.csv`.
